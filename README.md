# Своим ходом

Личное приложение для тех, кто путешествует своим ходом, без туроператора: билеты, брони, события, визы, страховки, маршруты и файлы событий в одном месте.

Приложение: https://anna1986.github.io/svoim-hodom/
Работает на телефоне и компьютере, открывается без интернета, можно установить на главный экран.

## Что умеет

- **Поездки**: текущая, предстоящие и прошедшие, с отсчётом дней до начала
- **Папки внутри поездки**: авиабилеты, поезда и автобусы, жильё, аренда авто, экскурсии и билеты, визы, страховки, маршруты, другое
- **План по дням**: автоматически собирается из броней (вылет, прилёт, заселение, выезд), подсвечивает ближайшее событие
- **Стоимость**: необязательная сумма и валюта для авиабилетов, поездов/автобусов, событий и жилья; за все билеты в записи или весь период проживания, без пересчёта валют
- **Файлы**: к любой записи можно прикрепить PDF, скриншот или фото, а потом открыть, сохранить или переслать
- **Участники событий**: приглашение по ссылке с выбором доступа — только событие с файлами (просмотр) или вся поездка (просмотр или редактирование)
- **Резервная копия**: экспорт и импорт всех данных вместе с файлами
- **Офлайн**: после первого открытия приложение работает без интернета
- **Синхронизация**: после входа по почте и паролю данные и файлы одинаковые на телефоне и компьютере

## Где хранятся данные

На каждом устройстве лежит полная копия в браузере (IndexedDB), поэтому приложение работает офлайн. После входа изменения отправляются в Supabase (проект `travel-helper`, регион Франкфурт):

- таблица `records`: поездки, записи и описания файлов (JSON), с пометкой удаления
- приватное хранилище `files`: сами файлы, лежат по пути `<user_id>/<attachment_id>`
- правила доступа (RLS) разрешают доступ владельцу и приглашённым участникам в пределах выданного доступа

Как устроена синхронизация (`src/sync.ts`): каждое локальное изменение попадает в очередь исходящих, при появлении сети очередь отправляется, затем забираются изменения с сервера, появившиеся после прошлой синхронизации. Если у записи есть неотправленное локальное изменение, побеждает локальное.

Отдельного раздела для паспортов и других личных документов нет. Файлы прикрепляются к записям внутри поездок. Старые личные документы сохраняются только для совместимости с существующими данными, синхронизацией и резервными копиями; автоматически они не удаляются.

## Структура

```
src/
  db.ts            модель данных и хранилище
  trip.ts          план по дням и даты поездки
  backup.ts        резервная копия
  sync.ts          синхронизация с Supabase
  supabase.ts      подключение к Supabase
  pages/           экраны
  components/      общие элементы и вложения
sw-template.js     service worker для работы офлайн
public/            иконки и манифест
docs/              видение и решения
```

## Запуск локально

```
npm install
npm run dev
```

## Приглашения на события

В карточке события владелец нажимает «Добавить участника» и выбирает «Только это событие» или «Вся поездка». Для поездки доступны просмотр и редактирование; отдельное событие открывается только для просмотра. После входа по ссылке участник подтверждает присоединение. Приглашённые события доступны на странице поездок отдельным списком.

Доступ только к событию реализован серверными RLS-политиками для записи события и его вложений. Данные остальных записей и сама поездка не выдаются. Экран приглашённого события загружается по интернету отдельно от локальной базы поездок. Ссылки на файлы подписываются на час; уже выданная ссылка продолжает действовать до истечения срока даже после удаления участника.

Ссылку можно отправить нескольким людям. Отзыв ссылок останавливает новые присоединения; доступ уже присоединившихся закрывается удалением участника. Удаление участника события не отменяет независимо выданный доступ ко всей поездке. Если удалить событие или сменить его папку, его приглашения отзываются, а участники события удаляются.

Перед публикацией интерфейса необходимо применить `supabase/migrations/20261116_event_members.sql` в проекте Supabase после существующих миграций. Проверка прав с тестовыми пользователями выполняется на локальной базе командой `psql -v ON_ERROR_STOP=1 -f supabase/tests/event_members.sql`; тест откатывает свои данные. Не публикуйте интерфейс до применения миграции.

Проверка стоимости билетов и приватности общих ссылок (Node.js 22.18+): `node --test tests/money.test.mjs tests/share-price.test.mjs`.
